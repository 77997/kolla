Add the APT repository

Debian 13 (trixie) or newer, on a ppc64el host. Install the signing key:

sudo install -d -m 0755 /etc/apt/keyrings
sudo curl -fsSL https://77997.github.io/kolla/ppc64le/repo-key.asc \
     -o /etc/apt/keyrings/kolla-ppc64le.asc

Then declare the source. It is a flat repository, so the suite is ./ and there is no component:

sudo tee /etc/apt/sources.list.d/kolla-ppc64le.sources >/dev/null <<'EOF'
Types: deb
URIs: https://77997.github.io/kolla/ppc64le/apt
Suites: ./
Architectures: ppc64el
Signed-By: /etc/apt/keyrings/kolla-ppc64le.asc
EOF

The repository also carries Grafana, OpenSearch, ProxySQL and fluent-package for the Kolla container images. On a general-purpose host you usually want only the packages you asked for, so pin the rest out of consideration: 

sudo tee /etc/apt/preferences.d/kolla-ppc64le >/dev/null <<'EOF'
Package: *
Pin: origin 77997.github.io
Pin-Priority: -1

Package: src rsct.* devices.chrp.base.servicerm dynamicrm
Pin: origin 77997.github.io
Pin-Priority: 500
EOF
sudo apt-get update

Install RMC (RSCT) on a Debian guest

Resource Monitoring and Control is what lets an HMC or NovaLink drive DLPAR operations, Live Partition Mobility and serviceable events against a Linux LPAR. IBM ships RSCT for Ubuntu only; these packages are the same IBM sources rebuilt against Debian.

This only applies to a PowerVM LPAR managed by an HMC or NovaLink. A KVM guest on PowerNV — including an OpenStack instance — has no HMC to register with, and does not need RSCT. 

sudo apt-get install -y \
    src rsct.core.utils rsct.core rsct.basic rsct.opt.storagerm \
    devices.chrp.base.servicerm dynamicrm \
    powerpc-ibm-utils

APT resolves the install order itself. Every dependency — mksh, perl-base, openssl, librtas2, libservicelog-1.1-1, bc — comes from Debian main. powerpc-ibm-utils is not an RSCT dependency but provides drmgr, which is what actually applies a DLPAR add or remove once RMC has delivered it.

Enable and verify

sudo /usr/sbin/rsct/bin/rmcctrl -p
sudo /usr/sbin/rsct/bin/lssrc -a

You want ctrmc active, alongside IBM.DRM, IBM.ServiceRM, IBM.HostRM and IBM.MgmtDomainRM. From the HMC, lspartition -dlpar should then list the partition with Active:<1>.

If RMC does not come up

Three causes account for nearly all of it:

  1. The guest was cloned from an image. Every guest built from one template inherits a single node ID in /var/ct/cfg/ct_node_id, and the HMC will only ever see one of them as active. Regenerate it per guest — at first boot, not at image build time: 
    sudo /usr/sbin/rsct/install/bin/recfgct
sudo /usr/sbin/rsct/bin/rmcctrl -z
sudo /usr/sbin/rsct/bin/rmcctrl -A
sudo /usr/sbin/rsct/bin/rmcctrl -p
  2. Port 657 is blocked. RMC needs TCP and UDP 657 open in both directions between HMC and LPAR.
  3. The hostname does not resolve. RMC registers under the partition's own hostname; it must resolve to the LPAR's address in /etc/hosts.

Python wheel index

A PEP 503 index of ppc64le wheels for packages that publish no POWER build on PyPI. Point pip at it as an extra index — PyPI still wins wherever it has a matching wheel: 

pip install --extra-index-url https://77997.github.io/kolla/ppc64le/simple/ <package>

Browse the full list at /ppc64le/simple/.

Static binaries

/ppc64le/tarballs/ holds ppc64le builds of OpFlex, lego, cAdvisor, mtail and the Prometheus exporters, as plain tarballs for the image builds to unpack.
